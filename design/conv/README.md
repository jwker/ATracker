# 会话页两级菜单 · 布局设计

会话视图现在只有一级：所有会话平铺成一条横向小票条，目录只是相邻排列，看不出归属。这份稿子给会话页加一级目录，形成两级菜单。

## 打开方式

直接双击 `01-two-level-menu.html`。单文件，无构建步骤，无外部请求，离线可用，右上角可以切浅色和深色。

## 两个方案

**方案 A 横向两级**（页面主方案）。上面一条是目录，下面一条是当前目录下的会话。

一级目录横向排，按 token 降序，每项固定高度，内容是色块、目录名、会话数、token 和成本，底下有一条小横条表示这个目录占全部目录的比例。第一项是「全部」，等价于现在这个不分目录的平铺列表。

二级会话沿用现有的小票条（`.stub`），只是只列当前选中目录下的会话。切目录时二级整体替换，页面不跳。

**方案 B 纵向树**（备选）。目录一行，展开后缩进列出会话。层级一眼可见，目录多了要滚动，而且会话从横排变竖排，和现在的小票横条差别较大。

## 几个设计约定

- 目录颜色沿用 `dir_color` 表里已经分配好的颜色，颜色跟目录走不跟排名走。
- 一级和二级的每一项高度固定，切换目录时整块不跳。
- 一级里保留「全部」，不强迫用户先选目录。
- 已经按目录、来源或模型筛过时（`dir` / `agent` / `model`），一级默认选中对应目录，筛选条件变化时高亮跟着走；被筛掉的目录灰掉但不隐藏。
- 一级按 token 降序；二级按最后活跃时间降序，同一个会话只留一条。

## 落地时需要的东西

接口已经按目录分组了：`/api/conversations` 返回的 `groups` 里每个目录一组（`dir`、`total`、`list`），`list` 按最后活跃时间降序。前端只要在会话视图里加一个"当前目录"的状态，一级渲染 `groups`，二级渲染选中目录的 `list`。

状态可以放在 URL 上：`?view=conv&dir=<目录>`，这样目录可以分享、刷新不丢。

## 数据

页面里的数字来自本机 `data/atracker.db`，是真实目录和会话，只截取了前几个。
