# 当日详情页 · 设计稿

一个"今天用量详情"的页面稿，沿用 `design/v3/02-receipt.html` 的热敏小票风格：窄幅纸带、等宽排版、逐行小票、撕纸边。

## 打开方式

直接双击 `01-today-receipt.html`。单文件，无构建步骤，无外部请求，离线可用。右上角可以切浅色和深色。

页面里的数字是本机 `data/atracker.db` 的快照，由 `design/today/build.mjs` 生成：

```bash
node design/today/build.mjs              # 今天
node design/today/build.mjs 2026-10-20  # 指定某一天
```

脚本读 `template.html`，把数据填进去写成 `01-today-receipt.html`。改了版式就改模板，改了数据就重跑脚本。

## 页面回答的问题

页面按"总额 → 谁烧的 → 什么时候 → 哪些调用最贵 → 采集是否正常"的顺序排布，每一段对应一个具体问题，而不是把所有字段平铺在一张表里。

| 区块 | 回答的问题 | 数据来源 |
| --- | --- | --- |
| 今日合计 | 今天一共烧了多少 | `agg_day_*` 聚合表按天查 |
| 与昨天同一时刻对比 | 今天是不是异常 | 昨天到同一时刻的累计值 |
| TOKEN 四桶 | 缓存有没有生效 | `usage_event` 的四个 token 桶，思考 token 是输出的子集 |
| 来源 × 模型 | 哪个 agent 用哪个模型 | `agg_day_agent_model` |
| 一天之内 | 钱是几点花的 | `usage_event` 按小时分组 |
| 按来源 | 哪个 agent 烧的 | `agg_day_agent` |
| 按模型 | 哪个模型烧的，有没有缺价 | `agg_day_model` 加 `pricing.json` |
| 按目录 | 哪个项目烧的 | `agg_day_dir` 加 `dir_color` |
| 当天的会话 | 哪些会话在跑 | `usage_event` 按会话分组 |
| 最贵的几次调用 | 具体是哪几次 | `usage_event` 按成本排序 |
| 采集状态 | 采集本身正常吗 | `scan_batch` 与缺价计数 |

## 与昨天同一时刻的对比

这一项是页面里最有用的一栏，但也是唯一需要额外计算的一栏。当天数据在一天中是不断增长的，直接拿今天到现在和昨天一整天比，会得出"今天比昨天贵三倍"这种误导结论。正确做法是把两个数截到同一时刻：今天的累计值取到当前时间，昨天取到昨天同一时刻的累计值。页面底部同时标注昨天全天的数，读者能看出这一天还没过完。

## 落地时需要的东西

这个页面已经做进 React 应用了，页头多了一个「今日」标签，路由是 `#/today`，`#/today/YYYY-MM-DD` 打开某一天。

服务端新增 `GET /api/day?date=YYYY-MM-DD`，一次返回这一页需要的全部数据：四桶、小时分布、来源 × 模型、当天会话、最贵几次调用、采集状态。仓库层新增 `dayTotals`、`hourly`、`dayMatrix`、`daySessions`、`dayTopCalls`、`dayBatches` 六个查询。

和前一天比较时两边要截到同一时刻：今天的累计值取到当前时间，昨天取到昨天同一时刻的累计值，否则拿半天比一整天会夸大差距。仓库层用固定 UTC+8 折算，所以减一天就是前一天的同一时刻。

小时分布直接按 `ts` 分组查明细，没有加物化表。一天的明细在两千条量级，这个开销可以接受；如果以后单日明细涨到十万条，再加 `agg_hour` 表。

## 数据口径

- 日期和小时都按 Asia/Shanghai 折算，和 `packages/core/src/time.ts` 里的 `TZ` 一致，不依赖系统时区。
- 金额为估算值，缓存命中按缓存价计费，未定价的模型标为"未定价"并排除在金额合计外。
- 目录颜色来自 `dir_color` 表，跟着目录走，不跟着排名走。
- 页面里的数字是本机 `data/atracker.db` 的快照。数据库一直在被采集器写入，正式实现走接口取实时值。
