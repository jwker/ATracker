# ATracker · 十版界面设计

线框原型在 `design/wireframe`。这十个方向复刻了它的功能，但没有沿用它的 UI 与排版。每个方向都重新设计了信息架构、视觉语言和交互节奏，共用同一套数据与计算逻辑。

界面中不写模块编号（如 4.2、4.4.3）。层级通过标题、位置和分隔来表达，而不是需求文档式的编号。

## 打开方式

直接打开 `design/v3/index.html`，或单独打开任意一个 HTML。全部是静态文件，没有构建步骤，也没有网络请求。

- 总览：`?view=home`
- 会话：`?view=conv`
- 日志：`?view=log`

- `?theme=light` 或 `?theme=dark`
- `?unit=zh`、`?unit=abbr`、`?unit=full`

## 共享层

`data.js` 与 `_core.js` 不属于视觉设计，但十个页面都依赖它们：

- `data.js`：365 天、6 个目录、5 个来源、6 个模型、会话与轮次、扫描批次、日志。
- `_core.js`：状态、聚合、格式化、路由与事件挂载，通过 `window.TK` 暴露。
- 每个 HTML 只负责自己的结构、CSS 和渲染函数。

因此改数据或计算口径只需要改这两处，十个设计会一起变化。

## 复刻的功能

- 单位切换：中文单位、缩写、完整数字。
- 主题切换：每个方向都有独立的浅色与深色配色，不是简单反色。
- 月份切换与回到本月。
- 单日选择；再点另一天成区间；再点一次重置。
- 目录图例静音，静音后该目录从图表与合计中移除。
- 来源 × 模型矩阵下钻到对应会话。
- 目录条或目录图例下钻到该目录的会话。
- 会话搜索、按目录 / 来源 / 模型筛选、选择会话。
- 从会话回到日历并定位到该天。
- 日志按级别、来源、批次、关键词筛选，清除筛选，重新扫描。
- 所有金额与 token 数跟随当前选区变化。

## 数据与口径

- 金额为估算值。四个 token 桶按桶计价：输入 / 输出 / 缓存命中 / 缓存写入。
- 人民币按固定汇率 6.5 折算，不随日期变化。
- 日期按 Asia/Shanghai 折算自然日。
- 子 agent 的用量归入发起它的那一轮，不重复计数。
- 有一个模型没有定价，相关金额会标注为未定价并排除在金额合计之外。
- 目录颜色跟随实体，不跟随排名。筛选或静音后颜色不会重新分配。

## 验证

- 十个文件的内联脚本都通过 `node --check`。
- 每个方向的总览、会话、日志都在 1440px 下截图检查过。
- 浅色与深色都单独检查过；05 与 09 的深色是重新配的纸色与油墨，不是反相。
- 390px 宽度下检查了单列布局、表格横向滚动、标签换行与缩略图裁切。
- 十份文件都没有模块编号文本，也没有外部字体、图片或脚本请求，离线可用。

## 已知取舍

- 04 的通道推子采用 0 到 25% 的固定刻度，并直接标出占当前范围总量的百分比。六个目录本身差距不大，所以推子高度接近是数据的真实形状，不是渲染问题。
- 01 与 05 的模型条按占总量比例绘制，和旁边的百分比标签一致；目录条也使用同一口径。
- 02 是窄幅版式，在宽屏上居中显示，不为了填满宽度而拉伸。
- 05 的柱状日历把每天当作一列，列内按目录堆叠；点列即选日，和原始日历的选择行为一致。
- 07 在 560px 以下会隐藏画廊缩略图里的最后一行示例数据，给合计行让位；这只是画廊预览，不影响页面本身。
- 10 的矩阵用单色深浅表示 token 量，颜色只承担量级，实体身份由行列标题与悬停提示承担。
