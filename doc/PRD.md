# ATracker 需求文档（PRD）

版本：v1 · 2026-10-20

## 1. 背景与目标

本机同时装着 codex、Claude Code、pi、opencode、DeepSeek Harness 五个 AI 编码 agent，每个都把用量记在自己家目录里，彼此不通。要做一个只读的本地看板，把这些日志汇总成统一口径的 token 与成本数据，并提供两个视图：主页面（日历）和对话页。

约束有三条：不加任何钩子、不改 agent 行为、不上传任何数据。采集、计算、存储、展示全部在本机完成。

## 2. 口径定义

这一节是后面所有展示规则的基础。

### 2.1 token 的四个桶

每个来源的用量统一拆成四桶，含义固定：

| 桶 | 含义 |
| --- | --- |
| 输入 | 未命中缓存的输入 |
| 输出 | 模型输出，含推理 token |
| 缓存命中 | 读取缓存的部分 |
| 缓存写入 | 首次写入缓存的部分 |

推理 token 是输出的子集，只做单独展示，不重复计入总量。

总量 = 输入 + 输出 + 缓存命中 + 缓存写入。

各 agent 的原始字段到这四个桶的转换规则见 `doc/PLAN.md` 第 3.1 节。其中 codex 的 `input_tokens` 含缓存，需要减去 `cached_input_tokens`。

### 2.2 数字的三种显示单位

所有显示 token 的地方都提供三种单位，用户可以切换。同一份数据在三种单位下的读数不同，切换时重新换算，不是只改后缀。

| 类型 | 名称 | 例子 | 换算规则 |
| --- | --- | --- | --- |
| A | 中文单位 | 2.41 亿 | 亿 = 10⁸，万 = 10⁴ |
| B | 缩写单位 | 241.0 M | B = 10⁹，M = 10⁶，K = 10³ |
| C | 千分位纯数字 | 241,000,000 | 无单位，三位一组加逗号 |

类型 A 只有「亿」和「万」两档，小于一万的数值直接用千分位整数：

| 数值区间 | 显示 |
| --- | --- |
| ≥ 10⁸ | 保留两位小数，单位「亿」，例如 2.41 亿 |
| 10⁴ ≤ 数值 < 10⁸ | 保留一位小数，单位「万」，例如 3,412.9 万 |
| < 10⁴ | 千分位整数，不带单位，例如 4,180 |

类型 B 的档位：≥ 10⁹ 显示两位小数的「B」，≥ 10⁶ 显示一位小数的「M」，≥ 10³ 显示一位小数的「K」，更小显示整数。

**注意类型 A 和 B 的读数不可直接互换。** 2.41 亿等于 241 M，因为亿是 10⁸ 而 B 是 10⁹。界面上切换单位时必须整块重算，不能只替换单位后缀。

类型 C 用于需要精确值的地方，比如表格里的单行数值、成本计算依据、价格表配置。

**单位是全局设置。** 顶栏一处切换，整页所有数字跟着变，包括主页面、对话页、日历格子和所有表格。不存在某个模块单独用某种单位的情况。

唯一的例外是 4.1 的 token 总量，那一块固定用千分位整数做主数字，另外两种读法放在小字里（见 4.1）。

### 2.3 货币

价格以人民币元为主显示，美元作为小字副单位跟在后面。

- 成本表 `config/pricing.json` 的计价单位是「每百万 token」。
- 每条价格可以带 `currency` 字段，不写默认 `USD`。官方价格用哪种货币就填哪种，中国厂商用 `CNY`。
- 引擎内部把全部金额折算成人民币再汇总，美元副单位按固定汇率 6.5 反算，所以填 `CNY` 的条目显示出来就是官方原值。汇率固定写死，不做配置项。
- 显示形式：主单位是大字的人民币金额，副单位是小字的美元金额，例如「¥11,979.90」配小字「$1,842.60」。
- 没有任何价格配置的模型，成本留空，显示「—」，并在旁边注明「未配置价格」，不能按 0 计算。
- **所有来源一律按 API 单价计算。** 订阅不单独计费，所以不需要按 agent 区分价格。成本表保留 `byAgent` 段，确有必要时可以在里面按 agent 覆盖。
- **成本表用人民币定价的模型（`currency: CNY`）以价格表为准**，不采用来源自报的美元成本；价格表用美元定价的模型优先用来源自报的值，因为它和表里的价格同单位。

### 2.3.1 缓存写入的计价

价格表里 `cache_write` 这一栏是「缓存写入桶的单价」。**厂商没有公布这一项时，统一按「统计到输入内」处理**：价格填 0，写入的那部分 token 计入输入桶，按输入价计费。

为什么这个规则成立，要看各家上报的字段：

| 厂商类型 | 上报字段 | 本项目四个桶的落法 |
| --- | --- | --- |
| 只报命中和未命中（DeepSeek、OpenAI） | 命中数、未命中数 | 未命中数进「输入」桶，写入的量也在里面；「缓存写入」桶恒为 0 |
| 单独报写入数（Anthropic、MiniMax 部分模型） | 输入、写入、读取三个数 | 三个数分别进三个桶 |

DeepSeek、智谱 GLM、MiniMax 这三家都没有单独的缓存写入价，按上面的规则处理：写入的 token 统计在输入桶，缓存写入桶恒为 0。

**万一遇到厂商收费但没公布价格的情况**：暂按输入价填，并在 `note` 里写明「写入价未公布，暂按输入价估算」，这类模型的成本标 `estimated`，看板上不与确定值混在一起。目前本机的模型里没有属于这种情况的。

**按输入长度分档的模型**（例如 MiniMax-M3 的 512k 分界）阈值比较的量，按「该次请求的总输入」算，即未缓存输入加缓存命中。官方没有明确说明这一点，先按这个口径执行。

**已知比值规律**（来自 litellm 定价表里同时有写入价和输入价的 478 个模型）：写入价是输入价 1.25 倍的有 382 个，0 倍的有 40 个，1 倍的有 39 个，1.5 倍和 9 倍等零星几个。1.25 倍是 Anthropic 系的常见约定。

### 2.4 时间

- 库里存 UTC 时间戳，按日聚合时按本机时区（本机为 Asia/Shanghai）折算成自然日。
- 日期一律用 `YYYY-MM-DD` 显示，月用 `YYYY 年 M 月`。
- 成本按每条用量事件的发生时刻判定波峰波谷，逐条算，不按会话或按天汇总后算。

### 2.5 子 agent

Claude Code 的子 agent 和 codex 的派生线程有独立的用量记录。这些用量照常计入总量，但归属到父会话。看板上提供一个「含子 agent / 仅主 agent」的开关，切换的是过滤条件，不重新统计。

## 3. 全局规则

### 3.1 主题

页面右上角有一个亮色暗色切换按钮，切换后整个界面（背景、文字、图表、状态色）整体换一套配色。选择的结果记住，下次打开沿用。

**主题（风格）和明暗是两个独立的维度。** 现在的主题是「热敏小票」风格（`design/v3/02-receipt.html`），以后可以再加别的风格，各种风格各自都有明暗两套配色，互不影响。切换风格时用户选的明暗保持不变。

### 3.2 模块不写标题

页面上每个模块**不显示模块名称**，直接显示内容。

需要说明范围的地方，用一行小字说明当前口径，而不是用一个标题。例如详细数据区顶部只写「2026 年 10 月 · 31 天」，不写「详细数据」。

### 3.3 页面结构

界面有三个页面：

| 页面 | 作用 | 入口 |
| --- | --- | --- |
| 主页面（日历） | 看全局用量：总价、总数、日历、明细 | 默认打开 |
| 对话页 | 看某个目录某个会话的详细数据 | 页头的「对话页」按钮 |
| 日志页 | 看采集过程发生了什么 | 页头的「日志」按钮 |

页头右侧常驻其他页面的入口按钮，随时能跳回去。

### 3.4 颜色语义

| 用途 | 颜色 |
| --- | --- |
| 强调 | 蓝色，用于选中态、主按钮、当前值 |
| 正向 | 绿色，用量上升 |
| 负向 | 红色，用量下降或错误 |
| 目录 | 每个目录一个固定颜色，见 4.3.3 |
| 来源 | 每个 agent 一个固定颜色，用在交叉表的行首圆点，和目录色板是两套 |

## 4. 主页面（日历）

界面只有两个页面：主页面和对话页。主页面就是日历页，页面上从上到下是四块内容，顺序是 token 总量与预估价格、token 总数、日历视图、详细数据。

页头右侧有一个「对话页」按钮，跳到对话页。

### 4.1 token 总量与预估价格

页面最上面最大的一个模块。左边是 token 总量，右边是价格，同一个模块里。

**token 总量**

- 全站最大的数字，显示累计总 token 数。
- 主数字固定用千分位整数，不受全局单位设置影响。
- 总量 = 输入 + 输出 + 缓存命中 + 缓存写入。
- 累计值，不随日历的选中状态变化。
- 主数字下面一行小字说明总量的构成，再下面一行小字给出中文单位和缩写单位两种读法，中间用分隔符隔开。

**价格**

- 同一个模块里，用小字显示。人民币金额为主，美元金额更小，紧跟在后面。
- 汇率固定 6.5。
- 累计值，不随日历的选中状态变化。
- 存在缺价模型时，在下面用一行更小的字说明「N 个模型未配置价格，未计入」。

### 4.2 token 总数

累计用量拆成四项，每项一个数：

| 项 | 小字说明 |
| --- | --- |
| 输入 | 未命中缓存的部分 |
| 输出 | 含推理 token |
| 缓存命中 | 命中百分比 |
| 缓存写入 | 首次写入缓存的部分 |

四项的顺序固定为输入、输出、缓存命中、缓存写入，这样和详细数据里的构成条颜色顺序一致。

**命中百分比** = 缓存命中 token ÷ 总 token。它衡量的是「有多大比例的输入是重复内容」，比例越高说明缓存用得越省。百分比显示在缓存命中那一项的小字里。

这四项和 4.1 的总量都是累计值，不跟随日历筛选。数字的单位跟随全局单位设置。

### 4.3 日历视图

#### 4.3.1 基本规则

- 最小单位是「日」。顶部一排是月份切换：上一月、当前年月、下一月，以及「今天」。
- 网格按周一到周日排七列，上方有星期表头。
- 月里的日期按自然月排列，前后补空格占位。

#### 4.3.2 每个日期格子

每个格子里有三样东西，从上到下：

1. **日期数字**，小字。
2. **当天 token 总量**，大字。这是格子里最显眼的东西。
3. **一条等高、不等宽的分段长条**，横向铺满格子宽度。

分段长条的规则：

- 高度固定，所有日期、所有格子都一样。
- 每个目录占一段，颜色按目录色表。
- 每段的长度 = 该目录当天用量占当天总量的比例。
- 所有段的长度加起来正好是格子的 100%。当天没有用量的目录不占位置。

也就是说，这一行是当天用量的 100% 堆叠条，用量多的目录那一段就长。

当天的总量取自上面第 2 项，两者是同一份数据的两种画法：一个是总数，一个是构成。

#### 4.3.3 图例

日历顶部有一行图例，说明每种颜色代表哪个目录。

- 图例项的排序按该目录在当前月份的用量降序。
- 最多显示 8 个目录，超出的合并成「其他」，用中性灰。
- 颜色分配：一个目录一个固定颜色，由目录绝对路径算一个稳定哈希再映射到固定色板，保证同一个目录在任何页面、任何月份都是同一个颜色。
- 图例项可以点，点了下面只显示这个目录的用量（再点取消）。

#### 4.3.4 选中行为

点击日期格子进入「选中」状态，联动下方所有模块。

| 操作 | 结果 |
| --- | --- |
| 点一个日期 | 选中这一天，详细数据切到当天 |
| 再点另一个日期 | 选中这两天之间的区间（连续日期），详细数据切到区间合计 |
| 点已选中的那个日期 | 取消选中，回到当前月份 |
| 键盘左右方向键 | 上一个月 / 下一个月 |
| Esc | 取消选中 |

选中状态在格子边框上体现（强调色描边），并且日历顶部显示当前范围说明。

### 4.4 详细数据

详细数据的统计范围跟着日历的选中状态走：

| 选中状态 | 统计范围 | 顶部说明文字 |
| --- | --- | --- |
| 没选 | 当前月份 | 「2026 年 10 月 · 31 天」 |
| 选了一天 | 那一天 | 「2026-10-18」 |
| 选了区间 | 区间内所有天 | 「2026-10-18 → 2026-10-20 · 3 天」 |

这一块包含四块内容，从上到下：token 四桶的构成、来源 × 模型 交叉表、模型条形图、目录条形图。

#### 4.4.1 token 构成

四个桶各一个数：输入、输出、缓存命中、缓存写入。旁边给出区间总量。

构成用一条 100% 的堆叠条表示，段的顺序固定为输入、输出、缓存命中、缓存写入，这样跨范围对比时颜色位置不变。

#### 4.4.2 来源 × 模型 交叉表

一张交叉表，行是来源，列是模型，每格是这两个维度交叉处的 token 量。**底色的深浅表示量级**，格子里写具体数值。

| 元素 | 规则 |
| --- | --- |
| 行 | 五个来源各一行，行首是一个固定颜色的小圆点加来源名 |
| 列 | 用量最多的模型在前，最多 6 列，超出的合并成一列「其他」 |
| 格子 | 底色按这一格的量在表内最大值中的比例取色阶，数值居中；没有量显示「·」 |
| 合计 | 最后一行是各列的合计，最后一列是各行的合计 |
| 图例 | 表格上方一条色阶带，从浅到深，标「量级低 → 高」 |

颜色用主色的渐变，不另外引入一套配色。来源的圆点颜色用来源色板（见 3.4），和目录色板是两套，互不干扰。

**点格子下钻。** 点某一格，跳到对话页，并把来源和模型作为筛选条件带过去。对话页左栏顶部显示当前筛选和「清除」。

这个表回答的是「哪个 agent 在用哪个模型」。条形图只看单个维度的排序，交叉表能看出搭配关系，比如 codex 基本只用 gpt 系列、pi 主要用 deepseek 和 MiniMax。

#### 4.4.3 各模型使用 token 的横向条形图

按模型聚合当前范围的用量，降序排列。每行显示三样东西：

- 条形长度。
- 占比。
- token 数量。

#### 4.4.4 各目录使用 token 的横向条形图

结构和模型那张一样，按目录聚合。

和模型那张的区别是：目录条形的颜色用目录色表，和日历里的颜色一致，扫一眼能对上。条形图里某一行可以点击，跳到对话页并选中这个目录。

## 5. 对话页

从主页面页头的「对话页」按钮进入。页头右侧有一个「回到日历」按钮，返回主页面。

### 5.1 整体结构

单栏，从上到下：筛选与搜索区、目录条、会话条、会话详情。目录和会话是两级菜单：先选目录，再选这个目录下的会话。

### 5.2 目录与会话

从上到下：

1. **搜索框**，按目录名或会话摘要过滤。
2. **筛选条**，带着来源或模型的筛选条件进来时才出现。显示当前条件、当前会话数和「清除」。
3. **目录条（一级）**，横向一排，按 token 降序。第一项是「全部目录」，等于不分目录。每项显示色块、目录名、会话数、token、成本，底下一条小横条表示这个目录占全部目录的比例。目录颜色跟日历一致，跟着目录走不跟排名走。
4. **会话条（二级）**，只列当前选中目录下的会话，按最后活跃时间倒序。每条显示：标题（超长截断）、日期、来源、token 数量。

选中的目录写进 URL（`?view=conv&dir=<目录路径>`），刷新和分享都保留这一级。从别的页面带着目录钻进来时，一级默认选中那个目录。

会话按时间倒序，最近的在上。

### 5.3 右栏：会话详情

选中的会话是哪个，就展示哪个会话的详细数据。默认展开第一个会话。

从上到下五块：

**一、会话头**

- 会话标题或摘要。
- 来源标签、模型名、目录。
- 起止时间、轮次数、工具调用数。
- 右侧一个「在日历中查看这天」按钮，跳到主页面并选中这个会话所在的那一天。

  这个按钮给的是**那一天的全局用量**，不是这个会话的数据。日历的选中粒度只到天，选中后详细数据区显示的是那天所有会话的合计，这个会话只是其中一条。

**二、token 构成**

四个桶的数和总量，和主页面详细数据里的口径一致。下方一条 100% 堆叠条。

**三、成本**

- 人民币金额大字，美元金额小字。
- 逐日成本列表：哪天、花了多少。用于看出这个会话的成本集中在哪几天。
- 如果这个会话用到的模型有缺价的，标出来。

**四、逐轮明细表**

这是最细的一层，一行一轮次：

| 列 | 内容 |
| --- | --- |
| 时间 | 该轮发生的时刻 |
| 模型 | 这一轮用的模型，会话中途换模型时能看出来 |
| 输入 / 输出 / 缓存命中 | 这一轮的三个数 |
| 增量成本 | 这一轮的人民币成本 |
| 状态 | 成功、失败、进行中 |

子 agent 的轮次用缩进和标记区分，归属到发起它的那一轮下面。默认折叠，可以展开。

**五、口径说明**

一小段固定说明：这个会话的 token 怎么算的、时区是什么、子 agent 怎么归属的、成本从哪来。默认收起，展开后可见。

## 6. 日志页

从页头的「日志」按钮进入。这一页回答的是「采集过程发生了什么」：扫了哪些文件、跳过了哪些、报了什么错、价格有没有缺口、对账通没通过。

### 6.1 状态条

页面最上面一行，四个数：

| 内容 | 说明 |
| --- | --- |
| 最近扫描 | 时间，附触发方式和耗时 |
| 写入事件 | 事件数，附去重条数 |
| 跳过文件 | 指纹未变而跳过的文件数 |
| 警告 / 错误 | 两个数，附队列深度 |

这些是累计状态，不受日历选择影响。

### 6.2 扫描批次

一张表，每次扫描一行：

| 列 | 内容 |
| --- | --- |
| 时间 | 这次扫描的开始时间 |
| 触发 | 文件变更 / 兜底轮询 / 手动 |
| 耗时 | 毫秒 |
| 文件 | 实际解析的文件数 |
| 事件 | 写入的用量事件数 |
| 警告 / 错误 | 两个数，警告用黄、错误用红 |
| 结果 | 成功 / 有错误 |

**点一行**，下面的日志流筛到这一批；再点一次取消。右上角一个「重新扫描」按钮，触发一次手动扫描。

### 6.3 日志流

按时间倒序，一行一条：时间、级别、来源、消息。

级别有四种，用符号区分：

| 级别 | 符号 | 什么时候出现 |
| --- | --- | --- |
| 成功 | ✓ | 一个阶段做完了，比如「4,182 条用量事件已写入」 |
| 正常 | · | 过程信息，比如「读取 18 个 jsonl」 |
| 警告 | ! | 不影响结果但要注意，比如文件尾部不完整、有模型没配价 |
| 错误 | × | 某个来源这一批失败了，比如数据库被锁 |

左栏是筛选区：级别、来源（五个 agent 加「系统」和「价格」）、关键字搜索，再下面一个「清除筛选」。左栏底部是**诊断**区，列出每个来源当前能不能读、读到了多少文件。

消息的写法要求：

- 说清楚做了什么和数量，不写「处理成功」这种没信息量的话。
- 带文件名或路径前缀，定位到具体是哪个文件出的问题。
- 警告和错误要说清楚后果：跳过了什么、要不要人工处理。

### 6.4 与其他页面的关系

日志页和主页面读的是同一份数据的两个侧面：主页面看结果，日志页看过程。主页面上的「N 个模型未配置价格」提示，日志页里有一条对应的警告行，两边指向同一个问题。

## 7. 数据来源

界面上的每个数字都来自本地只读采集，各 agent 的原始文件位置和字段见 `doc/PLAN.md` 第 3 节。

| 界面数据 | 来源 |
| --- | --- |
| 每个会话每轮的 token | 各 agent 会话日志里的用量记录 |
| 目录 | 日志里的工作目录字段 |
| 模型与厂商 | 日志里的模型和厂商字段 |
| 成本 | `config/pricing.json` 手写价格表，按事件时间逐条算 |
| 缺失价格 | 价格表里没有该模型的条目 |

## 8. 异常与边界

| 情况 | 处理 |
| --- | --- |
| 模型没有配置价格 | 成本留空显示「—」，统计「未配置价格的模型数」，不按 0 计入总成本 |
| 某天没有用量 | 日历格子显示 0，堆叠条为空，不画线段 |
| 目录数量超过 8 个 | 图例取用量前 8 个，其余合并为「其他」 |
| 模型数量超过 6 个 | 交叉表只保留用量最多的 6 列，其余合并成「其他」列 |
| 某个来源和某个模型没有交集 | 格子显示「·」，底色为最浅的一档 |
| 会话被删除或日志被截断 | 该会话最后一条不完整记录跳过，扫描时记一条日志 |
| 父会话和子 agent 同时计入 | 子 agent 用量计入总量并归属父会话，只在明细里标记，不重复计数 |
| 跨零点的会话 | 按事件发生时刻归到对应自然日 |
| 目录被删除 | 日志里的路径照常计入，目录名就是路径末两段 |
