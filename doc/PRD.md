# ATracker 需求文档（PRD）

版本：v1 · 2026-10-20

## 1. 背景与目标

本机同时装着 codex、Claude Code、pi、opencode、DeepSeek Harness 五个 AI 编码 agent，每个都把用量记在自己家目录里，彼此不通。要做一个只读的本地看板，把这些日志汇总成统一口径的 token 数据，并提供两个视图：主页面（日历）和对话页。

约束有三条：不加任何钩子、不改 agent 行为、不上传任何数据。采集、计算、存储、展示全部在本机完成。

## 2. 口径定义

这一节是后面所有展示规则的基础。

### 2.1 token 的四个桶

每个来源的用量统一拆成四桶，含义固定：

| 桶 | 含义 |
| --- | --- |
| 输入 | 未命中缓存的输入 |
| 输出 | 模型输出，含推理 token |
| 缓存命中 | 读取缓存的部分 |
| 缓存写入 | 首次写入缓存的部分 |

推理 token 是输出的子集，只做单独展示，不重复计入总量。

总量 = 输入 + 输出 + 缓存命中 + 缓存写入。

各 agent 的原始字段到这四个桶的转换规则见 `doc/PLAN.md` 第 3.1 节。其中 codex 的 `input_tokens` 含缓存，需要减去 `cached_input_tokens`。

### 2.2 数字的三种显示单位

所有显示 token 的地方都提供三种单位，用户可以切换。同一份数据在三种单位下的读数不同，切换时重新换算，不是只改后缀。

| 类型 | 名称 | 例子 | 换算规则 |
| --- | --- | --- | --- |
| A | 中文单位 | 2.41 亿 | 亿 = 10⁸，万 = 10⁴ |
| B | 缩写单位 | 241.0 M | B = 10⁹，M = 10⁶，K = 10³ |
| C | 千分位纯数字 | 241,000,000 | 无单位，三位一组加逗号 |

类型 A 只有「亿」和「万」两档，小于一万的数值直接用千分位整数：

| 数值区间 | 显示 |
| --- | --- |
| ≥ 10⁸ | 保留两位小数，单位「亿」，例如 2.41 亿 |
| 10⁴ ≤ 数值 < 10⁸ | 保留一位小数，单位「万」，例如 3,412.9 万 |
| < 10⁴ | 千分位整数，不带单位，例如 4,180 |

类型 B 的档位：≥ 10⁹ 显示两位小数的「B」，≥ 10⁶ 显示一位小数的「M」，≥ 10³ 显示一位小数的「K」，更小显示整数。

**注意类型 A 和 B 的读数不可直接互换。** 2.41 亿等于 241 M，因为亿是 10⁸ 而 B 是 10⁹。界面上切换单位时必须整块重算，不能只替换单位后缀。

类型 C 用于需要精确值的地方，比如表格里的单行数值。

**单位是全局设置。** 顶栏一处切换，整页所有数字跟着变，包括主页面、对话页、日历格子和所有表格。不存在某个模块单独用某种单位的情况。

唯一的例外是 4.1 的 token 总量，那一块固定用千分位整数做主数字，另外两种读法放在小字里（见 4.1）。

### 2.3 不做金额

看板只显示 token，不显示成本和金额。这一条是 2026-10-31 改的，原来有人民币与美元双单位、价格表和固定汇率，整块去掉了。

原因是金额的口径收敛不出来：订阅制的渠道（`opencode-go`、`minimax-cn-coding-plan`）不按量计费；同一个模型名在不同渠道下价格不同；阶梯价和波峰波谷让单价随每次调用变化；价格表还会随模型更新迅速滞后。这些数加出来的总额看着精确到分，实际没有可比性。

token 数则相反：它是各 agent 自己记在日志里的，采集器只做单位归一，能复核。所以所有页面、所有排序、所有对比都只用 token。

替代品是精确且有决策价值的比例：主页面右上角显示**缓存命中率** = 缓存命中 ÷（未命中输入 + 缓存命中），它说明重复上下文占了多少，命中率低就说明每次都在重读同样的内容。

### 2.4 时间

- 库里存 UTC 时间戳，按日聚合时按本机时区（本机为 Asia/Shanghai）折算成自然日。
- 日期一律用 `YYYY-MM-DD` 显示，月用 `YYYY 年 M 月`。

### 2.5 子 agent

Claude Code 的子 agent 和 codex 的派生线程有独立的用量记录。这些用量照常计入总量，但归属到父会话。看板上提供一个「含子 agent / 仅主 agent」的开关，切换的是过滤条件，不重新统计。

## 3. 全局规则

### 3.1 主题

页面右上角有一个亮色暗色切换按钮，切换后整个界面（背景、文字、图表、状态色）整体换一套配色。选择的结果记住，下次打开沿用。

**主题（风格）和明暗是两个独立的维度。** 现在的主题是「热敏小票」风格（`design/v3/02-receipt.html`），以后可以再加别的风格，各种风格各自都有明暗两套配色，互不影响。切换风格时用户选的明暗保持不变。

### 3.2 模块不写标题

页面上每个模块**不显示模块名称**，直接显示内容。

需要说明范围的地方，用一行小字说明当前口径，而不是用一个标题。例如详细数据区顶部只写「2026 年 10 月 · 31 天」，不写「详细数据」。

### 3.3 页面结构

界面有三个页面：

| 页面 | 作用 | 入口 |
| --- | --- | --- |
| 主页面（日历） | 看全局用量：总价、总数、日历、明细 | 默认打开 |
| 对话页 | 看某个目录某个会话的详细数据 | 页头的「对话页」按钮 |
| 日志页 | 看采集过程发生了什么 | 页头的「日志」按钮 |

页头右侧常驻其他页面的入口按钮，随时能跳回去。

### 3.4 颜色语义

| 用途 | 颜色 |
| --- | --- |
| 强调 | 蓝色，用于选中态、主按钮、当前值 |
| 正向 | 绿色，用量上升 |
| 负向 | 红色，用量下降或错误 |
| 目录 | 每个目录一个固定颜色，见 4.3.3 |
| 来源 | 每个 agent 一个固定颜色，用在交叉表的行首圆点，和目录色板是两套 |

## 4. 主页面（总账与月度）

页头有五项导航：总账、月度、今日、会话、日志。前两个是主页面，区别只有一个——**作用域**。

| 页面 | 作用域 | 内容 |
| --- | --- | --- |
| 总账 | 全部记录 | 全期总量与缓存命中率、四桶、来源 × 模型、模型用量、目录用量 |
| 月度 | 一个月或一个选区 | 范围标签、总量与缓存命中率、四桶、月历、来源 × 模型、模型用量、目录用量 |

拆成两个页面的原因是原来一页里并存两种作用域：顶部的「当前范围 / 全部记录」切换器只管一个大数字，其余区块却跟着日历选区走，切换逻辑不自洽。现在每个页面只有一种作用域，页面上没有作用域切换器。

总账页顶部用一行静态说明交代时间范围（「全期 · 覆盖 42 天 · 2026-06-11 → 2026-10-31」）。日历只在月度页。

### 4.1 token 总量与缓存命中率

页面最上面最大的一个模块。左边是 token 总量，右边是缓存命中率，同一个模块里。

**token 总量**

- 全站最大的数字：总账页是全期累计，月度页是当月或选中区间的合计。
- 总量 = 输入 + 输出 + 缓存命中 + 缓存写入。
- 主数字下面一行小字说明这个数的口径：总账是「全期累计 / 四桶合计」，月度是「当月 / 覆盖 N 天」或「选中区间 / 覆盖 N 天」。

**缓存命中率**

- 公式：缓存命中 ÷（未命中输入 + 缓存命中）。两个数都直接来自日志，不需要推算。
- 大字显示百分比，下面一行小字给出命中量和未命中量的绝对值。
- 和左边的总量永远同一个口径：总账页取全期，月度页取当月或选区。
- 不看金额：看板不折算成本，理由见 2.3。

### 4.2 TOKEN 四桶

用量拆成四项，排在一条四格横排里（一行，标签在上、数值和占比在下），用点线与相邻格分隔。小屏折成两行两列。每项一个数：

| 项 | 小字说明 |
| --- | --- |
| 输入 | 未命中缓存的部分 |
| 输出 | 含推理 token |
| 缓存命中 | 命中百分比 |
| 缓存写入 | 首次写入缓存的部分 |

四项的顺序固定为输入、输出、缓存命中、缓存写入，这样和详细数据里的构成条颜色顺序一致。

**命中百分比** = 缓存命中 token ÷ 总 token。它衡量的是「有多大比例的输入是重复内容」，比例越高说明缓存用得越省。百分比显示在缓存命中那一项的小字里。

这四项和 4.1 的总量都是累计值，不跟随日历筛选。数字的单位跟随全局单位设置。

### 4.3 日历视图（只在月度页）

#### 4.3.1 基本规则

- 最小单位是「日」。顶部一排是月份切换：上一月、当前年月、下一月，以及「今天」。
- 网格按周一到周日排七列，上方有星期表头。
- 月里的日期按自然月排列，前后补空格占位。

#### 4.3.2 每个日期格子

每个格子里有三样东西，从上到下：

1. **日期数字**，小字。
2. **当天 token 总量**，大字。这是格子里最显眼的东西。
3. **一条等高、不等宽的分段长条**，横向铺满格子宽度。

分段长条的规则：

- 高度固定，所有日期、所有格子都一样。
- 每个目录占一段，颜色按目录色表。
- 每段的长度 = 该目录当天用量占当天总量的比例。
- 所有段的长度加起来正好是格子的 100%。当天没有用量的目录不占位置。

也就是说，这一行是当天用量的 100% 堆叠条，用量多的目录那一段就长。

当天的总量取自上面第 2 项，两者是同一份数据的两种画法：一个是总数，一个是构成。

#### 4.3.3 图例

日历上方有一行图例，说明每种颜色代表哪个目录。

- 图例只列**当前范围**用量前 6 个目录，其余合并成「其他」，用中性灰。范围跟着日历的选中走：没选日期就是当月，选了某几天就是那几天。
- 日历格子的堆叠条也只画这 6 个目录，其余合并成一个灰色的「其他」段。**范围外的格子不画堆叠条**，那个范围的目录排名和那天没关系，画了会误导。
- 颜色分配：一个目录一个固定颜色，由目录绝对路径算一个稳定哈希再映射到固定色板，保证同一个目录在任何页面、任何月份都是同一个颜色。
- 图例是说明，不再是开关：点它不做任何事，也就没有「静音某个目录」这回事。

#### 4.3.4 选中行为

点击日期格子进入「选中」状态，联动下方所有模块。

| 操作 | 结果 |
| --- | --- |
| 点一个日期 | 选中这一天，详细数据切到当天 |
| 再点另一个日期 | 选中这两天之间的区间（连续日期），详细数据切到区间合计 |
| 点已选中的那个日期 | 取消选中，回到当前月份 |
| 键盘左右方向键 | 上一个月 / 下一个月 |
| Esc | 取消选中 |

选中状态在格子边框上体现（强调色描边），并且日历顶部显示当前范围说明。

### 4.4 详细数据

详细数据的统计范围：总账页是全期；月度页跟着日历的选中状态走。

| 页面与选中状态 | 统计范围 | 范围标签文案 |
| --- | --- | --- |
| 总账 | 全部记录 | 「全期 · 覆盖 42 天 · 起始日期 → 最后一天」 |
| 月度，没选 | 当前月份 | 「2026 年 10 月 · 31 天」 |
| 月度，选了一天 | 那一天 | 「2026-10-18 · 1 天」＋「查看这天的明细 →」 |
| 月度，选了区间 | 区间内所有天 | 「2026-10-18 → 2026-10-20 · 3 天」 |

范围标签在月度页的总量之上，是页面上唯一的时间入口。单天选中时右侧出现「查看这天的明细 →」，跳到今日页；区间没有对应的明细页，所以不放入口。

这一块包含四块内容，从上到下：来源 × 模型 交叉表、模型条形图、目录条形图（四桶在 4.2，位于更上面）。

#### 4.4.1 token 构成

见 4.2 的四桶：一行四格，每格是「标签 / 数值 + 占比」。这里不再重复画一次。

#### 4.4.2 来源 × 模型 交叉表

一张交叉表，行是来源，列是模型，每格是这两个维度交叉处的 token 量。**底色的深浅表示量级**，格子里写具体数值。

| 元素 | 规则 |
| --- | --- |
| 行 | 五个来源各一行，行首是一个固定颜色的小圆点加来源名 |
| 列 | 用量最多的模型在前，最多 6 列，超出的合并成一列「其他」 |
| 格子 | 底色按这一格的量在表内最大值中的比例取色阶，数值居中；没有量显示「·」 |
| 合计 | 最后一行是各列的合计，最后一列是各行的合计 |
| 图例 | 表格上方一条色阶带，从浅到深，标「量级低 → 高」 |

颜色用主色的渐变，不另外引入一套配色。来源的圆点颜色用来源色板（见 3.4），和目录色板是两套，互不干扰。

**点格子下钻。** 点某一格，跳到对话页，并把来源和模型作为筛选条件带过去。对话页左栏顶部显示当前筛选和「清除」。

这个表回答的是「哪个 agent 在用哪个模型」。条形图只看单个维度的排序，交叉表能看出搭配关系，比如 codex 基本只用 gpt 系列、pi 主要用 deepseek 和 MiniMax。

#### 4.4.3 各模型使用 token 的横向条形图

按模型聚合当前范围的用量，降序排列。每行显示三样东西：

- 条形长度。
- 占比。
- token 数量。

#### 4.4.4 各目录使用 token 的横向条形图

结构和模型那张一样，按目录聚合。

和模型那张的区别是：目录条形的颜色用目录色表，和日历里的颜色一致，扫一眼能对上。条形图里某一行可以点击，跳到对话页并选中这个目录。

## 5. 对话页

从主页面页头的「对话页」按钮进入。页头右侧有一个「回到日历」按钮，返回主页面。

### 5.1 整体结构

单栏，从上到下：筛选与搜索区、目录条、会话条、会话详情。目录和会话是两级菜单：先选目录，再选这个目录下的会话。

### 5.2 目录与会话

从上到下：

1. **搜索框**，按目录名或会话摘要过滤。
2. **筛选条**，带着来源或模型的筛选条件进来时才出现。显示当前条件、当前会话数和「清除」。
3. **目录条（一级）**，横向一排，按 token 降序。第一项是「全部目录」，等于不分目录。每项显示色块、目录名、会话数、token，底下一条小横条表示这个目录占全部目录的比例。目录颜色跟日历一致，跟着目录走不跟排名走。
4. **会话条（二级）**，只列当前选中目录下的会话，按最后活跃时间倒序。每条显示：标题（超长截断）、日期、来源、token 数量。

选中的目录写进 URL（`#/conversations?dir=<目录路径>`），刷新和分享都保留这一级。从别的页面带着目录钻进来时，一级默认选中那个目录。

会话按时间倒序，最近的在上。

### 5.3 右栏：会话详情

选中的会话是哪个，就展示哪个会话的详细数据。默认展开第一个会话。

从上到下五块：

**一、会话头**

- 会话标题或摘要。
- 来源标签、模型名、目录。
- 起止时间、轮次数、工具调用数。
- 右侧一个「在日历中查看这天」按钮，跳到主页面并选中这个会话所在的那一天。

  这个按钮给的是**那一天的全局用量**，不是这个会话的数据。日历的选中粒度只到天，选中后详细数据区显示的是那天所有会话的合计，这个会话只是其中一条。

**二、token 构成**

四个桶的数和总量，和主页面详细数据里的口径一致。下方一条 100% 堆叠条。

**三、逐日用量**

- 这个会话在哪几天产生了用量，每天多少 token。
- 每行显示日期、占会话总量的百分比和绝对值。
- 会话跨天时能一眼看出用量集中在哪天。

**四、逐轮明细表**

这是最细的一层，一行一轮次：

| 列 | 内容 |
| --- | --- |
| 时间 | 该轮发生的时刻 |
| 模型 | 这一轮用的模型，会话中途换模型时能看出来 |
| 输入 / 输出 / 缓存命中 | 这一轮的三个数 |
| 合计 | 这一轮四桶相加 |
| 状态 | 成功、失败、进行中 |

子 agent 的轮次用缩进和标记区分，归属到发起它的那一轮下面。默认折叠，可以展开。

**五、口径说明**

一小段固定说明：这个会话的 token 怎么算的、时区是什么、子 agent 怎么归属的。默认收起，展开后可见。

## 6. 日志页

从页头的「日志」按钮进入。这一页回答的是「采集过程发生了什么」：扫了哪些文件、跳过了哪些、报了什么错、对账通没通过。

### 6.1 状态条

页面最上面一行，四个数：

| 内容 | 说明 |
| --- | --- |
| 最近扫描 | 时间，附触发方式和耗时 |
| 写入事件 | 事件数，附去重条数 |
| 跳过文件 | 指纹未变而跳过的文件数 |
| 警告 / 错误 | 两个数，附队列深度 |

这些是累计状态，不受日历选择影响。

### 6.2 扫描批次

一张表，每次扫描一行：

| 列 | 内容 |
| --- | --- |
| 时间 | 这次扫描的开始时间 |
| 触发 | 文件变更 / 兜底轮询 / 手动 |
| 耗时 | 毫秒 |
| 文件 | 实际解析的文件数 |
| 事件 | 写入的用量事件数 |
| 警告 / 错误 | 两个数，警告用黄、错误用红 |
| 结果 | 成功 / 有错误 |

**点一行**，下面的日志流筛到这一批；再点一次取消。右上角一个「重新扫描」按钮，触发一次手动扫描。

### 6.3 日志流

按时间倒序，一行一条：时间、级别、来源、消息。

级别有四种，用符号区分：

| 级别 | 符号 | 什么时候出现 |
| --- | --- | --- |
| 成功 | ✓ | 一个阶段做完了，比如「4,182 条用量事件已写入」 |
| 正常 | · | 过程信息，比如「读取 18 个 jsonl」 |
| 警告 | ! | 不影响结果但要注意，比如文件尾部不完整、来源目录不存在 |
| 错误 | × | 某个来源这一批失败了，比如数据库被锁 |

左栏是筛选区：级别、来源（五个 agent 加「系统」）、关键字搜索，再下面一个「清除筛选」。左栏底部是**诊断**区，列出每个来源当前能不能读、读到了多少文件。

消息的写法要求：

- 说清楚做了什么和数量，不写「处理成功」这种没信息量的话。
- 带文件名或路径前缀，定位到具体是哪个文件出的问题。
- 警告和错误要说清楚后果：跳过了什么、要不要人工处理。

### 6.4 与其他页面的关系

日志页和主页面读的是同一份数据的两个侧面：主页面看结果，日志页看过程。主页面缺数据时，日志页里通常有一行对应的警告说明原因。

## 7. 数据来源

界面上的每个数字都来自本地只读采集，各 agent 的原始文件位置和字段见 `doc/PLAN.md` 第 3 节。

| 界面数据 | 来源 |
| --- | --- |
| 每个会话每轮的 token | 各 agent 会话日志里的用量记录 |
| 目录 | 日志里的工作目录字段 |
| 模型与厂商 | 日志里的模型和厂商字段（厂商自报优先，没自报才按模型名推断） |

## 8. 异常与边界

| 情况 | 处理 |
| --- | --- |
| 模型名没见过 | 照常统计，厂商留空，只显示模型名 |
| 某天没有用量 | 日历格子显示 0，堆叠条为空，不画线段 |
| 目录数量超过 6 个 | 图例取当前范围用量前 6 个，其余合并为「其他」 |
| 模型数量超过 6 个 | 交叉表只保留用量最多的 6 列，其余合并成「其他」列 |
| 某个来源和某个模型没有交集 | 格子显示「·」，底色为最浅的一档 |
| 会话被删除或日志被截断 | 该会话最后一条不完整记录跳过，扫描时记一条日志 |
| 父会话和子 agent 同时计入 | 子 agent 用量计入总量并归属父会话，只在明细里标记，不重复计数 |
| 跨零点的会话 | 按事件发生时刻归到对应自然日 |
| 目录被删除 | 日志里的路径照常计入，目录名就是路径末两段 |

- 不做用户登录、多用户、云端同步。
