# 多设备同步

一台电脑上的用量只是一个子集。这个功能让几台机器（比如家里的 Mac mini 和带出门的 MacBook）把各自的汇总写进一个共享目录，读别人的文件把数字加到一起。

**文件各管各的，谁都不改别人的**，「合并」只发生在查询阶段。所以两台机器同时写入也不会互相覆盖，一方离线很久再上线也不会丢数据。

## 同步什么，不同步什么

| 数据 | 会不会进同步文件 |
| --- | --- |
| 每天、每来源、每模型、每目录的 token 汇总 | 会 |
| 会话标题、轮次数、四桶、总量 | 会 |
| 目录绝对路径（含用户名和项目结构） | 会 |
| 每一条调用的逐轮明细（时间、模型、四个桶） | 不会，只留在本机 |
| 提示词和回答的正文 | 从来不采集，也不上传 |

同步目录必须是一个**你信任的文件夹**。用 iCloud、Syncthing、Dropbox 都行，格式一样；不用云盘时把它指到局域网共享盘也可以。目录里的绝对路径会带着用户名和项目结构，别把同步目录设成公开共享的。

## 设备标识

一台机器一个 id，存在 `~/.atracker/device.json`，首次运行自动生成，名字默认取主机名，可以直接改文件里的 `name`：

```json
{ "id": "a1b2c3d4-…", "name": "my-macbook", "platform": "darwin" }
```

命令行和桌面版共用这一份身份文件。两者的数据库位置不同（开发时是 `data/atracker.db`，桌面版是 `~/Library/Application Support/ATracker/atracker.db`），但设备是同一台，身份不该跟着库走。

库里带设备维度：`usage_event.device` 记这一行是哪台机器产生的，四张 `agg_day_*` 的主键都是 `(day, device, …)`。升级时历史行会自动认领给本机，不用手动迁移。

`ATRACKER_DEVICE_FILE` 可以指定身份文件的位置，测试用。

## 同步文件的格式

按「设备 + 月」拆文件，`atracker-<设备id>-<YYYY-MM>.jsonl`，每个几十 KB。每行一个 JSON 对象，三种行：

| 行类型 | 内容 |
| --- | --- |
| `device` | 设备自述，包含 id、名字、平台 |
| `agg` | 日级聚合，`k` 字段区分 agent / dir / model / agent_model 四种维度 |
| `session` | 会话汇总：标题、轮次数、四桶、总量 |

导入按「设备 + 月」整块替换（先删再插），重复导入是幂等的。本机自己的文件会被跳过——本机的数据本来就该从明细重算。重建聚合时只重算「明细里有数据的设备」，所以本机重扫不会把远端设备的行删掉。

## 怎么开

```bash
# 服务端自动同步：扫描完写自己的文件，启动时和每 60 秒读别人的文件
atracker serve --sync

# 指定任意目录（Syncthing、Dropbox、局域网共享盘都行）
atracker serve --sync-dir ~/Sync/ATracker

# 只想同步一次、不开服务
atracker sync export [--dir <目录>]
atracker sync import [--dir <目录>]
```

同步目录的优先级：`--sync-dir` > `--sync`（用 iCloud 默认目录 `~/Library/Mobile Documents/com~apple~CloudDocs/ATracker`）> 环境变量 `ATRACKER_SYNC_DIR` > `~/.atracker/config.json` 里的 `syncDir`。都没配置就关掉，不读也不写。

桌面版在「文件 → 多设备同步」里开关，切换时写进 `~/.atracker/config.json`，不用重启。「文件 → 同步目录…」可以换成任意文件夹，选完自动打开同步，当前路径显示在菜单项右侧。

日志页有一块「多设备同步」面板：目录、上次导出、上次对表（读了几份文件、导入了多少行）、错误，以及每台设备的最后写入时间、改名 / 忽略 / 恢复。**忽略**会删掉本机库里这台设备的行并停止导入，同步目录里对方写的文件不动，随时可以恢复——选择忽略而不是删除文件，是因为那些文件属于另一台机器，删掉是越权，而且下次同步还会被写回来。

`GET /api/sync` 返回同样的信息。

## 两台机器怎么配起来

前提：两台机器登录同一个 Apple ID，并且都打开了 iCloud Drive（系统设置 → Apple 账户 → iCloud → 「iCloud 云盘」）。没开的话，菜单里勾选同步会弹提示，勾自动弹回去。

**第一台**

1. 装好 ATracker，打开。
2. 菜单「文件 → 多设备同步（iCloud）」勾上。
3. 打开日志页，往下有「多设备同步」：同步目录应该是 `…/com~apple~CloudDocs/ATracker`，上次导出显示「刚刚 · N 个文件」，设备列表里只有这一台，标着「（本机）」。
4. 到 Finder 里看 iCloud Drive → ATracker，应该能看到 `atracker-<设备id>-<月>.jsonl`。

**第二台**

1. 同样装好、打开。
2. 同样勾上「多设备同步（iCloud）」。**路径不用填**——勾选时它算出这台机器自己的 iCloud 路径，写到这台机器的 `~/.atracker/config.json`。两台机器上的路径字符串不一样，但指的是云端的同一个文件夹。
3. 等 iCloud 把第一台的文件同步过来（几十秒到几分钟），再等最多 60 秒让 ATracker 对一次表。
4. 日志页的同步面板里会出现两台设备。总账、月度、今日三页会出现设备切换条：`全部设备 / 这台（本机）/ 那台`。

**验证通了没有**：两台机器的总账页都切到「全部设备」，看全期的覆盖天数和总量应该一致。

## 出问题时按这个顺序查

| 现象 | 先看什么 |
| --- | --- |
| 勾选后提示目录不存在 | iCloud Drive 没开，或者 iCloud 目录被改名了 |
| 面板里只有本机 | 对方的文件还没写进 iCloud，或者 iCloud 还没同步下来（去 Finder 里看有没有对方的文件） |
| 有对方文件但设备列表里没有 | 「上次对表」是不是几十秒内；「错误」有没有内容 |
| 有对方设备但数字不对 | 切到「全部设备」再看；确认两台机器的时区一致（写死在 `core/time.ts`） |
| 同一个项目在两台机器上分成两个目录 | 目录按绝对路径归并，`/Users/a/proj` 和 `/Users/b/proj` 就是两条记录，这是设计如此 |
| 点开对方的会话没有逐轮明细 | 明细不同步，只同步标题、轮次数、四桶和总量 |

## 设备过滤的默认值

设备切换条在库里超过一台设备时出现，总账、月度、今日三页都有。**默认只算本机**：不带 `device` 参数时接口按本机返回，「全部设备」要显式写 `?device=all`。

默认值放在服务端而不是前端，是因为前端曾经有过「点了全部设备但数字没变」的 bug——前端拿着默认值再传回去，服务端又按默认值覆盖了一遍。

今日页按范围区分：切到别的设备时，小时图、最大的几次调用、采集状态整块隐藏（这些依赖逐轮明细，不同步），顶部给一句说明。会话页把本机和远端的会话合在一起列，远端会话带设备名标签，点进去显示汇总，逐轮明细那段换成「明细在那台设备上」的说明。
