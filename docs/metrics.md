# 口径

这份文档定义看板上每个数字怎么算。页面上所有数字都按这里的规则来，改口径先改这里。

## token 的四个桶

每个来源的用量统一拆成四个桶，含义固定：

| 桶 | 含义 |
| --- | --- |
| 输入 | 未命中缓存的输入 |
| 输出 | 模型输出，含推理 token |
| 缓存命中 | 读取缓存的部分 |
| 缓存写入 | 首次写入缓存的部分 |

推理 token 是输出的子集，只单独展示，不重复计入总量。

**总量 = 输入 + 输出 + 缓存命中 + 缓存写入。**

各 agent 的原始字段到这四个桶的转换规则见 [采集器](architecture.md#2-数据如何触发获取)与[容易踩的坑](pitfalls.md)。其中 codex 的 `input_tokens` 含缓存部分，必须减去 `cached_input_tokens` 才是上表的「输入」。

## 缓存命中率

页面上代替金额位置的那个百分比：

```
缓存命中率 = 缓存命中 ÷（输入 + 缓存命中）
```

两个数都直接来自日志，不需要推算。它有决策价值：命中率低说明每次都在重读同样的上下文。折算成金额做不到这一点，原因见[为什么不折算金额](why-no-cost.md)。

## 三种显示单位

所有显示 token 的地方都支持三种单位，顶上切换一次全站跟着变——不是只换后缀，是整块重算。

| 类型 | 名称 | 例子 | 换算 |
| --- | --- | --- | --- |
| A | 中文单位 | 2.41 亿 | 亿 = 10⁸，万 = 10⁴ |
| B | 缩写单位 | 241.0 M | B = 10⁹，M = 10⁶，K = 10³ |
| C | 千分位数字 | 241,000,000 | 无单位，三位一组 |

类型 A 的两档边界：

| 数值区间 | 显示 |
| --- | --- |
| ≥ 10⁸ | 两位小数 +「亿」，例如 2.41 亿 |
| 10⁴ ~ 10⁸ | 一位小数 +「万」，例如 3,412.9 万 |
| < 10⁴ | 千分位整数，例如 4,180 |

类型 B 从大到小依次是两位小数的 B、一位小数的 M、一位小数的 K，再小显示整数。

类型 A 和 B 的读数不能直接互换：2.41 亿等于 241 M，因为亿是 10⁸、B 是 10⁹。切换单位时必须整块重算。

类型 C 用于需要精确值的地方，比如表格里的一行。例外是总账页的主数字，那一块固定用千分位整数，另外两种读法放在小字里。

## 时间

库里存 UTC 时间戳，按本机时区折算成自然日。日期统一用 `YYYY-MM-DD`，月份用 `YYYY 年 M 月`。

时区写死在 `packages/core/src/time.ts`，不是读系统时区——多设备同步时两台机器必须用同一套分桶边界，否则同一天的用量会分到两天去。

## 子 agent

Claude Code 的子 agent 和 codex 的派生线程有独立的用量记录。这些用量计入总量，但归属到父会话。会话页提供「含子 agent / 仅主 agent」开关，切换的是过滤条件，不重新统计。

## 厂商

用量按「厂商 + 模型」两个维度记录。厂商取采集器自报的 provider 原值，只有采集器没上报时才按模型名推断（`packages/core/src/catalog.ts`）。同名模型在不同渠道下必须分开统计，否则看不出用量走的是哪条线。

## 调用次数

调用次数只有本机能算——同步文件里只存聚合，不含逐轮明细。所以切到「全部设备」或别的设备时，界面上「N 次调用」这一段直接不显示，而不是只显示本机的那个数。
